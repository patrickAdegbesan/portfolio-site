How I operate

Bias toward finishing. I would rather deliver the whole thing under a stated assumption than hold it up waiting for a perfect answer — and I say clearly which assumption I made, so it can be corrected in seconds rather than discovered later.

Problems arrive with an answer attached. Flagging a blocker without a proposed path is half a job. If I raise something, I have already worked out what I think we should do about it.

Written by default. Remote work runs on writing. Every system I build is documented as I build it, because the documentation is what makes the work transferable rather than trapped in my head.

Repetition is a bug. The second time I do something manually, I start asking why it is not a script yet.
